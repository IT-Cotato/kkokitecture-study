# FFmpeg로 이해하는 비디오 인코딩 기초

---

# 1. 영상 파일은 왜 이렇게 큰가?

## 핵심 내용

비디오는 짧은 시간 동안 수많은 이미지를 연속해서 보여주는 데이터이다.

예를 들어 다음 조건의 원본 영상을 생각할 수 있다.

- 해상도: 1920×1080
- 색상: 픽셀당 24비트
- 프레임레이트: 초당 30프레임

압축하지 않은 1초 분량의 대략적인 데이터 크기는 다음과 같다.

```text
1920 × 1080 × 24bit × 30frame
≈ 1.49Gbit
≈ 186MB
```

1분이면 약 11GB에 이르므로 원본 상태로 저장하거나 전송하기 어렵다.

따라서 실제 비디오 서비스에서는 영상 데이터를 압축하고, 사용자의 단말과 네트워크 환경에 맞게 변환해야 한다.

# 2. 컨테이너와 코덱은 무엇이 다른가?

## 컨테이너

컨테이너는 비디오, 오디오, 자막, 메타데이터를 하나의 파일에 담는 형식이다.

대표적인 컨테이너는 다음과 같다.

- MP4
- MOV
- MKV
- WebM
- AVI

확장자가 `.mp4`라고 해서 내부의 비디오 압축 방식이 항상 같은 것은 아니다.

## 코덱

코덱은 비디오나 오디오 데이터를 압축하고 다시 해제하는 알고리즘이다.

대표적인 비디오 코덱은 다음과 같다.

- H.264/AVC
- H.265/HEVC
- VP9
- AV1

FFmpeg에서 자주 사용하는 H.264 인코더 구현체로 `libx264`가 있다. x264는 H.264/AVC 형식의 비디오를 인코딩하는 소프트웨어이다.[^1]

AOMedia는 AV1을 이전 세대 코덱보다 높은 압축 효율을 목표로 설계한 공개 비디오 코덱으로 설명한다.[^2]

## 비유

```text
컨테이너 = 택배 상자
코덱 = 상자 안의 물건을 압축하는 방법
```

하나의 MP4 컨테이너에는 H.264 비디오와 AAC 오디오가 함께 들어갈 수 있다.

```text
video.mp4
├─ Video Stream: H.264
├─ Audio Stream: AAC
└─ Metadata
```

# 3. 영상 품질을 결정하는 주요 요소

## 3.1 해상도

해상도는 한 프레임을 구성하는 픽셀 수이다.

| 이름 | 일반적인 해상도 |
|---|---:|
| 360p | 640×360 |
| 720p | 1280×720 |
| 1080p | 1920×1080 |
| 4K UHD | 3840×2160 |

해상도가 높을수록 더 세밀한 표현이 가능하지만 처리할 픽셀과 데이터양도 증가한다.

## 3.2 프레임레이트

프레임레이트는 1초 동안 표시되는 프레임 수이다.

- 24fps: 영화에서 자주 사용
- 30fps: 일반 영상에서 널리 사용
- 60fps: 게임이나 스포츠처럼 움직임이 빠른 영상에 적합

프레임레이트가 높을수록 움직임이 부드럽지만 필요한 데이터와 인코딩 연산도 증가한다.

## 3.3 비트레이트

비트레이트는 1초 동안 처리하거나 전송하는 데이터양이다.

```text
파일 크기 ≈ 비트레이트 × 영상 길이
```

예를 들어 5Mbps로 인코딩한 60초 영상은 오디오와 기타 데이터를 제외하면 대략 다음 크기를 가진다.

```text
5Mbit/s × 60s ÷ 8
≈ 37.5MB
```

같은 해상도라도 비트레이트가 너무 낮으면 다음 현상이 나타날 수 있다.

- 화면의 블록 현상
- 세부 묘사 손실
- 빠른 움직임에서 잔상과 깨짐
- 색상 경계의 뭉개짐

## 핵심 관계

```text
높은 해상도·프레임레이트·비트레이트
→ 일반적으로 높은 화질
→ 더 큰 파일
→ 더 높은 네트워크·저장·연산 비용
```

# 4. I·P·B 프레임과 GOP

비디오 압축은 모든 프레임을 완전한 이미지로 저장하지 않는다.

## 프레임 종류

### I 프레임

다른 프레임의 정보 없이 독립적으로 복원할 수 있는 완전한 프레임이다.

- 임의 위치 탐색에 필요
- 오류 복구의 기준점
- 데이터 크기가 비교적 큼

### P 프레임

이전 프레임을 기준으로 달라진 부분을 저장한다.

### B 프레임

이전 프레임과 이후 프레임을 함께 참조하여 차이를 저장한다.

x264는 적응형 B 프레임 배치와 여러 참조 프레임 등의 기능을 제공한다.[^1]

## GOP

GOP는 I 프레임에서 시작하여 연속된 P·B 프레임을 하나로 묶은 단위이다.

```text
I  B  B  P  B  B  P  B  B  I
|--------- GOP ---------|
```

### GOP가 짧을 때

- 탐색과 오류 복구가 쉬움
- 라이브 스트리밍과 편집에 유리
- I 프레임이 많아져 파일 크기가 증가할 수 있음

### GOP가 길 때

- 압축 효율이 좋아질 수 있음
- 임의 위치 탐색과 복구가 느려질 수 있음

# 5. 트랜스코딩과 FFmpeg

## 트랜스코딩

트랜스코딩은 기존 비디오를 다른 형식으로 변환하는 과정이다.

변경 가능한 요소는 다음과 같다.

- 코덱
- 컨테이너
- 해상도
- 프레임레이트
- 비트레이트
- 오디오 형식

유튜브와 같은 서비스는 하나의 원본을 여러 품질로 변환한다.

```text
원본 영상
├─ 360p
├─ 720p
├─ 1080p
└─ 4K
```

사용자는 네트워크 상태와 단말 성능에 맞는 버전을 재생한다.

## FFmpeg

FFmpeg는 비디오와 오디오를 변환하고 처리할 수 있는 명령행 도구 모음이다.

- `ffmpeg`: 변환, 인코딩, 필터 적용
- `ffprobe`: 미디어 파일 구조와 스트림 정보 분석
- `ffplay`: 간단한 미디어 재생

FFmpeg 공식 프로젝트는 `ffmpeg`를 멀티미디어 변환 도구, `ffprobe`를 멀티미디어 분석 도구로 설명한다.[^3]

## 기본 명령 구조

```bash
ffmpeg -i 입력파일 [옵션] 출력파일
```

```text
입력 디코딩
→ 필터 처리
→ 출력 인코딩
→ 컨테이너에 저장
```

# 6. FFmpeg 실습

## 6.1 영상 정보 확인

```bash
ffprobe -v error \
  -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate,bit_rate \
  -show_entries format=duration,size,bit_rate \
  -of default=noprint_wrappers=1 \
  input.mp4
```

확인할 수 있는 주요 정보는 다음과 같다.

- 비디오·오디오 코덱
- 해상도
- 프레임레이트
- 비트레이트
- 재생 시간
- 전체 파일 크기

`ffprobe`는 스트림별 코덱과 비트레이트 등을 선택하여 출력할 수 있다.

## 6.2 720p H.264 영상 생성

```bash
ffmpeg -i input.mp4 \
  -vf "scale=-2:720" \
  -c:v libx264 \
  -preset medium \
  -crf 23 \
  -c:a aac \
  -b:a 128k \
  output_720p.mp4
```

### 옵션 해석

| 옵션 | 의미 |
|---|---|
| `-i input.mp4` | 입력 파일 지정 |
| `-vf "scale=-2:720"` | 세로 720px로 조정하고 가로 비율은 자동 계산 |
| `-c:v libx264` | H.264 비디오 인코더 사용 |
| `-preset medium` | 인코딩 속도와 압축 효율의 균형 설정 |
| `-crf 23` | 화질 중심의 품질 수준 설정 |
| `-c:a aac` | 오디오를 AAC로 인코딩 |
| `-b:a 128k` | 오디오 비트레이트를 128kbps로 설정 |

FFmpeg 공식 문서는 입력, 필터, 인코더, 출력 옵션을 조합해 미디어를 변환하는 명령 구조를 제공한다.[^5]

## 6.3 360p·720p·1080p 변환 비교

```bash
ffmpeg -i input.mp4 -vf "scale=-2:360"  -c:v libx264 -crf 23 -c:a aac output_360p.mp4
ffmpeg -i input.mp4 -vf "scale=-2:720"  -c:v libx264 -crf 23 -c:a aac output_720p.mp4
ffmpeg -i input.mp4 -vf "scale=-2:1080" -c:v libx264 -crf 23 -c:a aac output_1080p.mp4
```

### 비교할 항목

- 파일 크기
- 인코딩 시간
- 화면의 세부 묘사
- 빠르게 움직이는 장면의 품질
- 작은 화면과 큰 화면에서의 체감 차이

# 7. 품질·용량·속도의 트레이드오프

비디오 인코딩에서 하나의 설정이 항상 가장 좋은 것은 아니다.

## CRF

CRF는 일정한 화질을 목표로 비트레이트를 장면마다 다르게 배분하는 방식이다.

일반적인 `libx264` 사용에서는 다음과 같이 이해할 수 있다.

```text
낮은 CRF
→ 높은 품질
→ 큰 파일

높은 CRF
→ 낮은 품질
→ 작은 파일
```

## Preset

Preset은 인코더가 압축을 위해 얼마나 많은 연산과 탐색을 수행할지 정한다.

```text
빠른 preset
→ 짧은 인코딩 시간
→ 같은 품질에서 파일이 커질 수 있음

느린 preset
→ 긴 인코딩 시간
→ 같은 품질에서 압축 효율이 좋아질 수 있음
```

## 서비스별 선택

| 상황 | 우선 고려 요소 |
|---|---|
| 실시간 방송 | 낮은 지연과 빠른 인코딩 |
| VOD 플랫폼 | 화질과 압축 효율 |
| 모바일 업로드 | 업로드 속도와 데이터 사용량 |
| 영상 보관 | 저장 비용 |
| 편집용 원본 | 높은 품질과 편집 편의성 |

# 8. 핵심 정리

- 컨테이너는 비디오·오디오·메타데이터를 담는 형식이다.
- 코덱은 비디오 데이터를 압축하고 해제하는 방식이다.
- 영상 품질과 용량은 해상도, 프레임레이트, 비트레이트의 영향을 받는다.
- I·P·B 프레임과 GOP를 이용해 중복 데이터를 줄인다.
- 트랜스코딩은 원본 영상을 여러 단말과 네트워크 환경에 맞게 변환하는 과정이다.
- FFmpeg와 ffprobe를 사용하면 미디어 분석과 변환을 직접 실습할 수 있다.
- 실제 서비스에서는 품질, 용량, 처리 속도 사이의 균형이 중요하다.
