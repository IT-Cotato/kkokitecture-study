## 1. Googlebot이란

- 구글이 운영하는 웹 크롤러로, 검색 엔진 인덱싱을 위해 웹 페이지를 수집하는 역할
- 전체 봇 트래픽의 약 29%를 차지할 만큼 가장 많이 쓰이는 웹 크롤러
- 구글은 전 세계 검색 시장의 89.9%를 점유하며 하루 약 85억 건의 검색을 처리한다. Googlebot이 페이지를 제대로 크롤링하지 못하면 그 페이지는 검색 결과에 노출되지 않는다.
- 단순히 하나의 독립 프로그램이 아니라, 구글 내부 중앙화된 크롤링 플랫폼(SaaS)의 한 클라이언트다. Google Shopping, AdSense 등 구글의 다른 제품들도 동일한 시스템을 통해 각자 다른 크롤러 이름으로 크롤링 요청을 보낸다. 서버 로그에 Googlebot이 찍히면 그건 Google Search 전용이다.
- Googlebot은 스마트폰 버전과 데스크톱 버전 두 가지로 운영된다

## 2. 동작 원리 — 3단계

### 1단계 — 크롤링 (Crawling)

Googlebot이 이전에 방문한 모든 페이지는 새로운 링크의 출처가 된다. 페이지를 크롤링할 때 외부 링크를 추출해 우선순위가 매겨진 크롤 큐에 추가한다. XML 사이트맵은 사이트에 어떤 페이지가 있는지, 마지막으로 업데이트된 시점이 언제인지 Googlebot에게 알려주는 구조화된 파일로, 대형 사이트나 내부 링크가 아직 없는 신규 콘텐츠에 특히 유용하다.

### 2단계 — 렌더링 (Rendering)

Googlebot이 가져온 바이트는 구글 서버에서 실행되는 브라우저 역할을 하는 Web Rendering Service(WRS)로 전달된다. WRS는 JavaScript 실행, 클라이언트 사이드 코드 처리, CSS 및 XHR 요청 처리 등 현대 브라우저가 하는 모든 작업을 수행한다.

단, JavaScript가 많은 페이지는 렌더링 큐에 별도로 넣어 처리하기 때문에 지연이 발생한다. 렌더링 지연의 중간값은 10초이며, 상위 90% 구간에서는 3시간, 상위 99% 구간에서는 18시간까지 지연되는 것으로 나타났다.

### 3단계 — 인덱싱 (Indexing)

크롤링이 자동으로 인덱싱으로 이어지지는 않는다. 페이지가 방문되었지만 인덱스에 추가되지 않을 수 있고, 반대로 인덱싱된 상태에서 재크롤링이 이루어지지 않을 수도 있다.

## 3. 크롤 버짓 (Crawl Budget)

Googlebot은 모든 페이지를 무한정 크롤링하지 않는다. 사이트마다 크롤링에 쓸 수 있는 자원이 정해져 있는데 이를 크롤 버짓이라고 한다.

**크롤 버짓을 결정하는 두 가지 요소**

- **크롤 속도 제한(Crawl Rate Limit):** Googlebot이 서버에 과부하를 주지 않고 크롤링할 수 있는 최대 속도. 서버 응답이 느리면 자동으로 속도를 줄인다.
- **크롤 수요(Crawl Demand):** 구글이 해당 URL을 얼마나 크롤링하고 싶은지를 나타내며, 백링크 수, 트래픽, PageRank, 콘텐츠 업데이트 빈도 등을 기반으로 결정된다.

**우선순위 결정 방식**

페이지에 내부 링크가 많이 연결될수록 중요한 콘텐츠로 인식되어 더 자주 크롤링된다. 반면 내부 링크가 없는 고립된 페이지는 기술적으로 접근 가능하더라도 크롤링되지 않는 경우가 많다. 자주 업데이트되는 페이지는 더 자주 재방문한다.

**크롤 버짓이 낭비되면 생기는 일**

크롤 버짓은 사이트 전체가 공유하는 자원이기 때문에, 가치 없는 페이지가 버짓을 소비하면 정작 중요한 페이지가 크롤링되지 못하는 상황이 발생한다. 예를 들어 이커머스 사이트에서 필터 조합으로 생성된 수만 개의 URL을 Googlebot이 크롤링하느라 바빠지면, 새로 등록한 상품 페이지는 몇 주가 지나도 인덱싱되지 않을 수 있다. 이 상태가 지속되면 신규 콘텐츠가 검색 결과에 아예 노출되지 않는 문제로 이어진다.

크롤 버짓 최적화는 페이지 수가 1만 개 이상인 경우부터 의미 있고, 10만 개 이상에서는 핵심 과제가 된다.

## 4. 크롤링 용량 제한

Googlebot은 개별 URL당 최대 2MB까지만 가져오며, HTTP 요청 헤더도 이 용량에 포함된다. 2MB를 초과하는 부분은 가져오지도, 렌더링하지도, 인덱싱하지도 않는다. PDF의 경우 최대 64MB까지 허용된다.

2MB 제한은 각 리소스에 개별적으로 적용된다. 외부 JavaScript 파일을 불러오는 경우 그 파일은 별도의 2MB 허용량을 가지며, 메인 HTML의 용량에 포함되지 않는다.

## 5. 실제 크롤링 문제 사례

구글은 2025년 크롤링 문제를 분석한 연간 보고서를 공개했다.

**패싯 네비게이션 (50%):** 이커머스 사이트에서 가격, 카테고리, 제조사 등 다양한 조건으로 필터링할 때 수많은 URL 조합이 생성된다. 예를 들어 색상 5가지, 사이즈 5가지, 가격 범위 4가지를 조합하면 100개의 URL이 만들어지는데, 이 조합이 수백만 개 단위로 불어나면 Googlebot이 이를 모두 탐색하려다 서버에 과부하가 걸린다. 구글 내부 보고서에서 크롤링 문제의 절반을 차지할 만큼 가장 흔하고 심각한 문제다.

**액션 파라미터 (25%):** `?add_to_cart=true` 같이 페이지 콘텐츠를 바꾸지 않고 특정 동작만 실행하는 URL 파라미터가 URL 공간을 두 배, 세 배로 불필요하게 늘리는 문제. 같은 상품 페이지인데 파라미터가 붙은 버전과 안 붙은 버전을 Googlebot이 별개의 URL로 인식해 각각 크롤링 시도를 한다.

**관련 없는 파라미터 (10%):** UTM 추적 파라미터나 세션 ID처럼 Googlebot이 콘텐츠 변경 여부를 판단하기 어려운 파라미터가 불필요한 크롤링을 유발. `?utm_source=instagram`이 붙은 URL과 안 붙은 URL이 동일한 페이지임에도 Googlebot 입장에서는 다른 URL이기 때문에 둘 다 크롤링하게 된다.

**WordPress 플러그인 (5%):** 이벤트 추적 등을 추가하는 플러그인이 예상치 못한 URL을 생성하거나 크롤링 경로를 복잡하게 만들어 크롤링 문제를 일으키는 경우. 오픈소스 특성상 플러그인마다 동작 방식이 달라 구글도 대응이 어렵다고 밝혔다.

## 6. 모바일 우선 인덱싱

Googlebot은 스마트폰 버전과 데스크톱 버전 두 가지 크롤러로 운영된다. Googlebot Smartphone은 모바일 사용자처럼 동작하고, Googlebot Desktop은 데스크톱 브라우저처럼 동작한다.

2025년 기준 모바일 우선 인덱싱이 전 세계 모든 사이트에 완전히 적용되었다. 구글은 현재 모바일 버전을 크롤링, 인덱싱, 순위 결정의 기준으로 삼는다. 데스크톱 버전은 더 이상 검색 노출의 주요 기준이 아니다.

모바일 사이트에 콘텐츠가 누락되어 있거나, 구조화 데이터가 다르거나, 특정 리소스가 차단되어 있으면 구글은 데스크톱 버전에 해당 내용이 있더라도 알 수 없다. 

Googlebot Smartphone은 JavaScript 렌더링으로 인해 기존 텍스트 전용 크롤러보다 페이지당 더 많은 크롤 버짓을 소비한다. 따라서 모바일 버전이 무거울수록 크롤 버짓 낭비로 이어질 수 있다.
