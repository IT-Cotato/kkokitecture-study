# 9장. 웹 크롤러 설계

> 웹크롤러란 검색 엔진에서 널리 쓰는 기술, 웹에 새로 올라오거나 갱신된 콘텐츠를 찾아내는 기술
> 

**크롤러의 이용**

- 검색 엔진 인덱싱: 크롤러는 웹 페이지를 모아 검색 엔진을 위한 로컬 인덱스를 만듦
    - Google bot
- 웹 아카이빙: 나중에 사용할 목적으로 장기보관하기 위해 웹에서 정보를 모으는 절차
    - 국립 도서관
- 웹 마이닝: 데이터 마이넝을 통해 인터넷에서 유용한 지식 도출
- 웹 모니터링: 인터넷에서 저작권이나 상표권이 침해되는 사례를 모니터링
    - 디지마크

웹크롤러는 처리하는 **데이터의 규모**에 따라 달라진다.

---

## 1단계 문제 이해 및 설계 범위 확정

웹 크롤러의 기본 알고리즘

1. URL 집합을 입력으로 해당 URL들이 가리키는 모든 웹 페이지를 다운로드 
2. 다운받은 웹 페이지에서 URL들을 추출
3. 추출된 URL들을 다운로드 할 URL 목록에 추가하고 1부터 반복

**웹크롤러를 만들때 필요한 요구사항**

1. 크롤러의 주된 용도르 알기
2. 수집하는 데이터의 양
3. 수집하는 웹 페이지의 범위
4. 수집한 웹 페이지의 저장 여부
5. 중복된 컨텐츠 처리 유무

**웹 크롤러가 만족 시켜야 할 속성**

- 규모 확장성: 웹은 수많은 페이지가 있기 떄문에 병행성을 활용하면 효과적으로 웹 크롤릴 가능
- 안전성: 크롤러는 웹의 비정상적인 입력에 잘 대응할 수 있어야 함
- 예절: 크롤러는 수집된 웹사이트에 짧은 시간동안 너무 많은 요청을 보내면 안 됨
- 확장성: 새로운 형태의 콘텐츠도 크롤링 할 수 있어야 함

## 2단계 개략적인 설계안 제시 및 동의 구하기

웹 크롤러에서 각 컴포넌트가 수행하는 기능

#### 시작 URL 집합

- 크롤링의 시작점
- 크롤러가 가능한 많은 링크를 탐색할 수 있도록 하는 URL를 고르는것이 중요
- URL 공간을 주제별로 세분화 한 다음 공간별로 다른 URL 사용

#### 미수집 URL 저장소

- 다운로드할 URL을 저장 관리하는 컴포넌트

**HTML 다운로더**

- 인터넷에서 웹 페이지를 다운로드하는 컴포넌트
- 다운로드할 페이지의 URL은 미수집 URL 저장소가 제공

#### 도메인 이름 변환기

- URL에 대응하는 IP주소를 알아내는 컴포넌트

#### 콘텐츠 파서

- 웹 페이지 다운로드 시 파싱과 검증 절차를 거쳐야 함
- 크롤링 서버에 콘텐츠 파서 구성시 크롤링이 느려지기 때문에 독립된 컴포넌트로 구성됨

#### 중복 콘텐츠인가?

- 실제 웹 페이지 콘텐츠는 중복이 많기 때문에 자료 구조를 도입하여 데이터 중복을줄이고
데이터 처리에 소요되는 시간을 줄임
- 이 방법은 웹 페이지의 해시값을 비교해 시간을 단축함

#### 콘텐츠 저장소

- 저장소를 고를때는 저장되는 데이터의 유형, 크기, 저장소 접근빈도, 데이터의 유효기간을 고려해 선택함

#### URL 추출기

- HTML 페이지를 파싱하여 링크를 골라내는 컴포넌트

#### URL 필터

- 다운로드 대상이 아닌 URL을 필터링하는 역할을 함

#### 이미 방문한 URL?

- 방문했던 URL을 추적하면 여러번 처리하는 일이 없어지기 때문에 서버 부하가 줄어들고 시스템이 무한 루프에 빠지지 않음
- 방문했던 URL이 저장되는 자료구조로는 블룸 필터나 해시 테이블이 자주 쓰임

#### URL 저장소

- 방문한 URL을 보관하는 저장소

#### 웹 크롤러 작업 흐름

1. 시작 URL을 미수집 URL 저장소에 저장
2. HTML 다운로더는 미수집 URL 저장소에서 URL 목록을 가져옴
3. HTML 다운로더는 도메인 이름 변환기를 사용해 URL의 IP 주소를 알아내고 다운받음
4. 콘텐츠 파서는 다운된 HTML 페이지를 파싱하여 올바른 형식을 갖춘 페이지인지 검증함
5. 콘텐츠 파싱과 검증이 끝난 후 중복 콘텐츠인지 확인 시작
6. 확인하기 위해 해당 페이지가 이미 저장소에 있는지 확인
    1. 저장소에 있으면 처리하지 않고 버림
    2. 저장소에 없으면 저장소에 저장한 후 URL 추출기로 전달
7. URL 추출기는 해당 HTML 페이지에서 링크를 골라냄
8. 골라낸 링크를 URL 필터로 전달
9. 필터링이 끝나고 남은 URL만 중복 URL 판별 단계로 전달
10. 이미 처리한 URL인지 확인 후 이미 저장된 URL은 버림
11. 저장소에 없으면 URL 저장소에 저장하고 미수집 URL 저장소에도 전달함

## 3단계 상세 설계

#### DFS를 쓸 것인가, BFS를 쓸 것인가

웹은 방향이 있는 그래프로 볼 수 있고 페이지는 노드, 하이퍼링크는 엣지라고 볼 수 있다. 따라서 크롤링 프로세스는 방향이 있는 그래프를 엣지를 따라 탐색하는 과정이다.
DFS, BFS는 Directed graph 탐색에 사용되는 두 가지 알고리즘인데 DFS(깊이 우선 탐색법)은 그래프 크기가 클 경우 어느 정도로 깊숙이 가게 될지 가늠하기 어려워 좋은 선택이가 아니다.
그래서 웹 크롤러는 BFS(너비 우선 탐색법)을 사용한다. BFS는 FIFO 큐를 사용하는 알고리즘이다.

**BFS의 두가지 문제점**

- 한 페이지에서 나오는 링크의 상당수는 같은 서버로 되돌아간다. 따라서 같은 호스트의 많은 링크를 다운받느라 크롤러가 바빠지게 되는데, 이때 링크의 처리가 병렬로 이루어지게 된다면 서버는 수많은 요청으로 부하가 걸리고 예의없는 크롤러가 된다.
- 표준적 BFS 알고리즘은 URL간 우선순위를 두지 않는데 모든 웹 페이지가 같은 수준의 중요성을 갖지 않는다. 따라서 페이지 순위, 트래픽 양, 업데이트 빈도 등 여러 척도에 따라 우선순위를 구별하는 것이 좋다.

#### 미수집 URL 저장소

미수집 URL의 저장소를 활용해 BFS의 문제를 쉽게 해결할 수 있다. 

**예의 있는 크롤러**

- 예의 있는 크롤러가 되기 위해서는  동일 웹 사이트에 대해서는 한 번에 한 페이지만 요청한다. 같은 웹 사이트의 페이지를 다운받는 태스크는 시간차를 두고 실행한다.
    - **큐 라우터**: 같은 호스트에 속한 URL은 언제나 같은 큐로 가도록 보장하는 역할
    - **매핑 테이블:** 호스트 이름과 큐 사이의 관계를 보관하는 테이블
    - **FIFO 큐**: 같은 호스트에 속한 URL은 언제나 같은 큐에 보관된다
    - **큐 선택기:** 큐 선택기는 큐들을 순회하면서 큐에서 URL을 꺼내서 해당 큐에서 나온 URL을 다운로드하도록 지정된 작업 스레드에 전달하는 역할을 한다
    - **작업 스레드**: 작업 스레드는 전달된 URL을 다운로드하는 작업을 수행한다. 전달된 URL은 순차적으로, 작업 사이에는 일정한 지연시간 존재

**우선순위**

- 유용성에 따라 URL 우선순위를 나눌 때는 페이지 랭크, 트래픽 양, 갱신 빈도 등 다양한 척도를 사용할 수 있다
    - **순위결정장치:** URL을 입력으로 받아 우선순위를 계산
    - **큐**: 우선순위별로 큐가 하나씩 할당, 우선순위가 높으면 선택될 확률 올라감
    - **큐 선택기**: 임의 큐에서 처리할 URL(우선순위 높을수록 더 자주 처리)을 꺼내는 역할 담당
    - **전면 큐**: 우선순위 결정 과정 처리
    - **후면 큐**: 크롤러가 예의바르게 동작하도록 보증

#### 신선도

웹페이지는 주기적으로 바뀌기 때문에 다운로드 된 페이지여도 재수집할 필요가 있다.
웹 페이지의 변경이력을 활용하거나 우선순위를 활용하여 중요한 페이지는 더 자주 재수집 한다.

**미수집 URL 저장소를 위한 지속성 저장장치**

안정성과 규모 확장성을 위해 대부분의 URL은 디스크에 두지만 IO 비용을 줄이기 위해 메모리 버퍼에 큐를 둔다.

#### HTML 다운로더

HTTP 프로토콜을 통해 웹 페이지를 내려 받는다.

**Robots.txt**

로봇 제외 프로토콜은 웹 사이트가 크롤러와 소통하는 표준적 방법. 크롤러가 수집해도 되는 페이지 목록이 들어 있다.

**성능 최적화**

1. 분산 크롤링
성능을 높이기 위해 크롤링 작업을 여러 서버에 분산하는 방법. 각 서버는 여러 스레드를 돌려 다운로드 작업을 처리한다.
2. 도메인 이름 변환 결과 캐시
도메인 이름 변환기는 크롤러 성능의 병목 중 하나. 병목을 줄이기 위해서 DNS 조회 결과로 얻어진 도메인 이름과 IP 주소 사이의 관계를 캐시에 보관해 놓고 크론 잡을 돌려 주기적으로 갱신하면 성능을 효과적으로 높일 수 있다.
3. 지역성
크롤링 작업을 수행하는 서버를 지역별로 분산하는 방법. 크롤링 서버와 크롤링 대상 서버와 지역적으로 가까우면 페이지 다운로드 시간은 줄어들기 때문
4. 짧은 타임아웃
어떤 웹 서버는 응답이 느리거나 응답하지 않기 때문에 일정시간 동안 서버가 응답하지 않으면 크롤러는 해당 페이지 다운을 중단함.

**안전성**

- 안정 해시: 다운로더 서버들에 부하를 분산할 때 적용 가능한 기술.
- 크롤링 상태 및 수집 데이터 저장: 장애가 발생한 경우에도 쉽게 복구할 수 있도록 크롤링 사태와 수집된 데이터를 지속적 저장장치에 기록함
- 예외 처리: 예외가 발생해도 전체 시스템 중단 안되도록 함
- 데이터 검증: 시스템 오류를 방지하기 위한 주요 수단

**확장성**

시스템은 계속 진화하기 때문에 확장가능성까지 염두해두고 설계해야한다

**문제 있는 콘텐츠 감지 및 회피**

1. 중복 콘텐츠
해시나 체크섬을 사용해 중복 콘텐츠를 보다 쉽게 탐지
2. 거미 덫
크롤러를 무한 루프에 빠뜨리도록 설계된 웹 페이지. 완전 회피 가능한 방법은 없기 때문에 수작업으로 URL 필터 목록에 넣어야함
3. 데이터 노이즈
가치가 없는 콘텐츠는 제외하고 작업

## 4단계 마무리

추가로 생각해 보면 좋을 것 

- 서버 측 렌더링: 링크를 즉석에서 만들어내는 경우에 서버 측 렌더링을 적용해 해결한다
- 원치 않는 페이지 필터링: 크롤링에 사용할 수 있는 자원은 유한하기 때문에 스팸 방지 컴포넌트를 두어 페이지를 걸러낸다
- 데이터베이스 다중화 및 샤딩: 다중화나 샤딩 같은 기법을 적용해 데이터 계층의 가용성 등을 향상시킴
- 수평적 규모 확장성: 대규모의 크롤링을 위해서는 자원이 많이 필요하기때문에 서버가 상태정보를 유지하지 않도록 한다
- 가용성, 일관성, 안정성
- 데이터 분석 솔루션
