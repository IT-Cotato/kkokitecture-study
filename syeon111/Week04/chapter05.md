# 5장. 안정 해시 설계

---

## 안정 해시 설계

> 수평적 규모 확장성을 달성하기 위해 요청/데이터를 서버에 균등하게 나눌 때 보편적으로 사용하는 기술
> 

---

### 해시 키 재배치 문제

서버 N개에 균등하게 부하를 나누는 가장 단순한 방법:

`serverIndex = hash(key) % N`

- 이 방식은 서버 수가 고정이고 데이터 분포가 균등할 때는 잘 동작
- 서버가 추가되거나 삭제되면 문제가 생김

**예시 (서버 4대 운영 중)**

| 키 | 해시값 | hash % 4 (서버 인덱스) |
| --- | --- | --- |
| key0 | 18358617 | 1 |
| key1 | 26143584 | 0 |
| key2 | 18131146 | 2 |
| ... | ... | ... |

서버 1이 장애로 죽으면 N이 3으로 줄어듦

→ `hash % 3`으로 바뀌면서 거의 모든 키의 서버 인덱스가 달라짐

→ 대부분의 클라이언트가 엉뚱한 서버에 접속

→ 대규모 cache miss 발생

---

### 안정 해시(Consistent Hash)

### 동작 원리

- 서버와 키를 모두 해시 링 위에 배치 (균등 분포 해시 함수 사용)
- 특정 키가 저장될 서버를 찾으려면, 키의 위치에서 시계 방향으로 탐색하며 만나는 첫 번째 서버에 저장
- 서버가 추가/삭제되어도 링 전체가 아닌 일부 키만 재배치되므로 영향 범위 최소화

---

### 두 가지 문제점

**1. 파티션 크기 불균등**

- 파티션 = 인접한 서버 사이의 해시 공간
- 서버가 추가/삭제되면 파티션 크기가 일정하지 않음
- 어떤 서버는 굉장히 작은 해시 공간, 어떤 서버는 굉장히 큰 해시 공간을 할당받음

**2. 키의 균등 분포 어려움**

- 서버 배치에 따라 특정 서버에 키가 몰릴 수 있다

---

### 가상 노드(Virtual Node)

- 두가지 문제점의 해결책
- 가상 노드는 실제 서버를 가리키는 가상의 노드
- 하나의 서버가 링 위에 여러 개의 가상 노드를 가지게 함
- 각 서버가 링 위의 여러 파티션을 분산해서 담당하게 됨
- 키의 위치에서 시계방향으로 탐색하다 만나는 첫 번째 가상 노드의 실제 서버에 저장

**가상 노드 수와 트레이드오프**

| 가상 노드 수 | 표준 편차 | 키 분포 | 필요 저장 공간 |
| --- | --- | --- | --- |
| 100개 | 평균의 약 10% | 덜 균등 | 적음 |
| 200개 | 평균의 약 5% | 더 균등 | 많음 |

→ 가상 노드 수가 많을수록 균등해지지만 메모리를 더 쓰기 때문에 시스템 요구사항에 맞게 적절히 조정해야 함

---

### 재배치할 키 결정

- 서버 추가 시: 새로 추가된 서버부터 반시계 방향의 첫 번째 서버 사이에 있는 키들만 새 서버로 재배치
- 서버 삭제 시: 삭제된 서버부터 반시계 방향의 첫 번째 서버 사이에 있는 키들을 인접 서버로 재배치

→ 전체 키를 다시 배치하는 것이 아니라 일부 키만 이동

---

### 안정 해시의 이점

- 재배치 키 최소화: 서버 추가/삭제 시 영향받는 키의 수가 최소화됨
- 수평적 규모 확장 용이: 데이터가 균등하게 분포되므로 서버를 자유롭게 늘리고 줄일 수 있음
- 핫스팟 키 문제 감소: 특정 샤드에 접근이 집중되는 과부하를 방지. 가상 노드로 데이터를 더 균등하게 분산시켜 이런 문제가 생길 가능성을 줄임
