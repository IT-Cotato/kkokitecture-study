# 글로벌 모바일 마케팅 플랫폼 Airship 분석 및 보안 아키텍처

## 핵심 요약

> **Airship은 단순한 '푸시 발송기'가 아닌, 앱 유저 유지를 극대화하는 엔터프라이즈 마케팅 자동화 플랫폼**
>
> - **핵심 가치:** iOS/Android 단일 통합 제어, 앱 업데이트가 필요 없는 실시간 인앱 UI 제어, MAU(월간 활성 사용자) 기반 비즈니스 모델.
> - **백엔드 핵심 과제:** 클라이언트 영역은 언제나 해킹 위험이 있으므로, 권한이 분리된 **Zero-Trust 아키텍처**를 완벽히 이해하고 서버 단에서 강력한 마스터 키를 격리·운영해야 함.

## 1. Airship 플랫폼 핵심 기능 및 포지셔닝

### 1-1. 왜 FCM/APNs 대신 Airship을 쓸까?

일반적인 푸시 발송(FCM, APNs)과 달리, Airship은 모바일 중심의 **고도화된 유저 경험 제어 솔루션**을 제공.

- **멀티채널 통합 푸시:** iOS, Android, Web 푸시는 물론 Apple/Google Wallet 패스까지 하나의 API 파이프라인으로 통합 관리.
- **인앱 경험 제안 :** 앱을 새로 빌드해서 스토어에 업데이트하지 않아도, 마케터가 대시보드에서 팝업창, 설문조사, 튜토리얼 화면을 디자인하고 특정 유저에게 실시간으로 띄울 수 있음.
- **실시간 타겟팅 및 세분화:** 유저의 실시간 행동(예: *'장바구니에 상품을 담고 1시간 동안 결제하지 않은 유저'*)을 트리거로 잡아 정교한 개인화 알림을 발송.

### 1-2. 타 플랫폼과의 포지션 차이

Airship은 '모바일 앱 리텐션과 고도화된 타겟 마케팅'에 특화.

| **플랫폼** | **주력 채널** | **주요 사용 목적** |
| --- | --- | --- |
| **Airship (에어쉽)** | **모바일 앱 푸시, 인앱 메시지** | **앱 사용자 유지 향상, 모바일 마케팅 자동화** |
| Twilio (트윌리오) | SMS, 음성 통화 | 시스템 연동, 인증번호 발송 등 인프라 중심 |
| Mailchimp (메일침프) | 이메일 | 뉴스레터, 대량 마케팅 이메일 발송 |

> **비즈니스 특징:** 건당 과금 중심인 문자/메일 플랫폼과 달리, Airship은 **월간 활성 사용자 수(MAU)** 및 기능 범위에 따라 엔터프라이즈 라이선스(월 고정비) 계약을 맺는 경우가 많아 대형 서비스에 매우 유리합니다.
>

## 2. Airship 보안 아키텍처: Zero-Trust Client

> 모바일 앱 코드는 해킹이나 리버스 엔지니어링을 통해 내부에 저장된 자격 증명이 언제든 유출될 수 있다는 **'신뢰할 수 없는 클라이언트'** 개념을 바탕으로 설계.
>

`[모바일 앱 (iOS/Android)] ──(유출 위험 존재)──> App Key / App Secret (최소 권한: 태그 수정만 가능)
[백엔드 서버 (Private)]   ──(철저 보안 구역)──> Master Secret / Bearer Token (강력 권한: 전체 푸시 발송)`

### 2-1. 키 자격 증명(Credentials)의 역할 분담

Airship은 클라이언트용 키와 서버용 키의 권한을 엄격하게 물리적으로 분리.

- **App Key & App Secret (앱 내부에 포함 가능)**
    - **위치:** 모바일 클라이언트 앱 소스코드 및 설정 파일
    - **역할:** 해당 디바이스를 Airship 플랫폼에 등록하고, 자기 자신의 태그를 수정하는 수준의 **최소 권한**만 가짐. 유출되더라도 타인에게 푸시를 쏘는 등의 악용이 불가능.
- **Master Secret / Bearer Token (앱 내부 포함 금지)**
    - **위치:** 백엔드 서버(Private Cloud / On-Premise) 내부
    - **역할:** 실제 전체 유저에게 푸시 메시지를 발송하고 시스템을 통제하는 키. 반드시 백엔드 서버의 환경변수로만 관리.

### 2-2. 태그 및 Named User 보안 주의사항

- **구조적 한계:** 유저의 관심사나 등급을 나누는 태그나 Named User 정보는 구조상 디바이스 단에서 직접 API를 호출해 수정할 수 있음. (악의적인 유저가 자신의 태그를 'VIP' 등으로 위변조 가능)
- **보안 가이드:** 타인의 푸시 토큰을 알아내는 것은 수학적으로 불가능하므로 타인의 데이터가 탈취될 위험은 낮으나, 본인의 식별자 변조 위험은 존재. 따라서 **태그나 네임드 유저 필드에는 주민등록번호, 계좌번호, 비밀번호 같은 민감한 개인정보를 저장하면 안됨.**

## 3. 백엔드 개발 및 로컬 테스트 가이드 (Java/Spring Boot)

### 3-1. 서버 환경 변수 분리 규칙

깃허브 등 오픈 소스 저장소에 강력한 권한의 Master Secret이 유출되는 사고를 막기 위한 백엔드 표준 코드 패턴.

- **Bad Case  (소스코드 내 하드코딩)**

    ```
    // 절대 소스코드에 키를 노출한 채로 Git에 push하면 안 됩니다.
    public static final String AIRSHIP_MASTER_SECRET = "AM_Secret_123456789_Unsecured";
    ```

- **Good Case  (Configuration 및 환경 변수 활용)**

    ```java
     // OS 환경변수 또는 application.yml에서 안전하게 주입받아 사용합니다. 
     @Value("${airship.master-secret}") private String masterSecret; 
    ```


### 3-2. 로컬(Localhost) 개발 환경 테스트 팁

- **발신(Outbound) 테스트:** Airship은 글로벌 클라우드 API 기반이므로, 내 컴퓨터가 인터넷에만 연결되어 있다면 로컬(Localhost)에서 서버를 띄워 호출해도 실제 스마트폰으로 푸시 알림이 정상 발송됩니다.
- **수신(Inbound/Webhook) 테스트:** 푸시 알림의 클릭 이벤트나 유저 오픈 데이터를 Airship 시스템으로부터 백엔드 웹훅으로 전달받아 테스트해야 할 때가 있습니다. 이때는 로컬 포트를 외부에 임시 퍼블릭 URL로 열어주는 **엔그록** 같은 터널링 툴을 활용하면 배포 없이도 완벽한 로컬 통합 테스트가 가능합니다.

## 4. 현실적인 도입 장벽 및 규모별 대안 기술

### 4-1. 개인 개발자나 초기 스타트업은 Airship을 쓰기 어려움

Airship은 처음부터 글로벌 트래픽을 보유한 **대기업을 타겟으로 설계**

- **최소 계약 비용 구조:** Twilio나 일반 문자/메일 플랫폼처럼 "이번 달에 100건만 썼으니 1,000원만 내기"가 불가능. 월간 활성 사용자(MAU) 기반의 연 단위/월 단위 고정 라이선스 계약이 기본이라 초기 비용 부담이 매우 큼.
- **가격 비공개 (B2B 영업 방식):** 홈페이지에 명확한 요금제가 명시되어 있지 않고, 대기업 고객사로서 영업 담당자와 미팅 및 견적 산출 과정을 거쳐야만 도입 가능.
- **과도한 스펙 오버:** 단순 공지사항이나 인증번호 푸시만 필요한 초기 서비스에게는 '실시간 지갑(Wallet) 연동'이나 '유저 행동 데이터 빅데이터 분석' 같은 Airship의 핵심 기능들이 오버엔지니어링이 될 수 있음.

### 4-2. 현실적인 단계별 대안

### ① 1단계: FCM (Firebase Cloud Messaging) + APNs

- **비용:** **100% 무료** (발송 건수 무제한)
- **특징:** 구글과 애플이 직접 제공하는 공식 푸시 인프라. 백엔드에서 FCM API를 호출하면 iOS와 Android 기기로 직접 푸시를 보낼 수 있음. 마케팅 대시보드는 없지만, **백엔드 개발자가 순수하게 푸시 발송 파이프라인과 아키텍처를 학습하고 구현하는 데 지장 없음**.

### ② 2단계: OneSignal (원시그널)

- **비용:** 무료 플랜 제공 (구독자 수 제한 내 무료, 이후 사용량 기반 종량제)
- **특징:** *FCM과 Airship의 중간에 위치하며* 글로벌 스타트업들이 가장 많이 찾는 보급형 에어쉽. 웹 UI가 매우 잘 구축되어 있어 개발자가 처음에 SDK 세팅만 해주면 마케터들이 직접 대시보드에서 푸시를 편하게 쏠 수 있음.
