## 📖 규모 확장
### 🔑 주요 개념
- 수평적 규모 확장
- 수직적 규모 확장

### 📝 수직적 규모 확장
- 서버에 고사양 자원을 추가하여 성능을 개선
- 트래픽 양이 적은 경우 유리
- 확장에 한계가 있음
- 장애 발생 시 웹/앱이 완전히 중단

### 📝 수평적 규모 확장
- 더 많은 서버를 추가하여 성능을 개선

### 📝 로드밸런서
#### 부하 분산 집합에 속한 웹 서버들에게 트래픽 부하를 분산
- 사용자는 로드밸런서의 공개 IP를 통해 접속
- 부하 분산 집합에 있는 서버들에게 트래픽을 분산(사설 IP 사용)

### 📝 데이터베이스 다중화
#### 주-부 관계를 설정하고 원본은 주 서버에, 사본은 부 서버에 저장
- 쓰기 연산은 마스터에서만 지원
- 부 데이터베이스는 읽기 연산만 지원
- 부 서버 다운 시 다른 부 서버나 주 서버로 연산 분산
- 주 서버 다운 시 부 서버 하나가 주 서버가 되고 필요한 경우 부 서버 추가 생성

#### 다중화로 얻는 이득
- 더 나은 성능 -> 읽기 연산 분산 가능
- 안정성 -> 서버 일부가 파괴되어도 데이터 보존
- 가용성 -> 하나의 db에 장애 발생 시 다른 db 사용하여 서비스 유지

## 📖 캐시
### 캐시 계층
- 데이터가 잠시 보관되는 곳
- DB보다 훨씬 빠르면서 DB 부하를 줄임
### 유의사항
- 데이터 갱신이 자주 일어나지 않고 참조는 자주 일어나는 경우 사용
- 휘발성 메모리에 두므로 영속적으로 보관할 데이터는 사용 x
- 원본과 차이가 나지 않을 정도의 적당한 만료 기간 설정
- 원본 갱신과 캐시 갱신 연산을 단일 트랜잭션으로 처리하여 일관성 유지
- 캐시 서버를 분산시켜 단일 장애 지점 문제 대비
- 캐시가 자주 밀려나지 않게 캐시 메모리를 과할당
- 캐시가 꽉 찬 경우 어떤 데이터를 먼저 내보낼지 적당한 방출 정책 선택 (LRU, LFU, FIFO)

## 📖 콘텐츠 전송 네트워크 (CDN)
### 정적 콘텐츠를 전송하는데 쓰이는 분산된 네트워크 
- 정적 컨텐츠는 웹 서버를 통하지 않고 CDN을 통해 제공
- 캐시가 데이터베이스의 부하를 줄여줌

### 동작 흐름
1. 사용자 A가 이미지 url을 통해 이미지에 접근
2. CDN 서버의 캐시에 해당 이미지가 없으면 원본 서버에 요청하여 파일 가져옴
3. 원본 서버가 파일을 CDN 서버에 반환 (TTL 값 포함)
4. CDN 서버는 파일 캐시하고 사용자 A에게 반환
5. 사용자 B가 같은 이미지 요청
6. TTL이 만료되지 않은 경우 캐시를 통해 처리

### 고려사항
- CDN에 들어가고 나가는 데이터 전송 양에 따라 과금 -> 자주 사용되는 컨텐츠만 캐싱
- 적절한 만료 시한 설정
- CDN 장애에 대한 대처 -> 문제 발생 시 원본 서버에서 가져오도록
- 만료되지 않은 컨텐츠를 버전 번호를 통해 수정하거나 API를 사용하여 무효화 가능

## 무상태 웹 계층
- 사용자로부터 HTTP 요청은 어떤 웹 서버로도 전달 가능
- 상태 정보가 필요한 경우 공유 저장소에서 데이터를 가져옴

## 데이터 센터
- 가용성을 높이고 쾌적하게 사용할 수 있는 환경을 제공
- 지리적 라우팅을 통해 가까운 데이터 센터로 안내
- 장애 발생 시 장애가 없는 데이터 센터로 트래픽 전송

### 고려사항
- 올바른 데이터 센터로 트래픽을 보내는 방법 강구
- 데이터 센터에 있는 데이터를 다중화하여 장애 상황 대비
- 여러 위치에서 테스트 필요

## 메세지 큐
- 무손실 보장
- 비동기 통신 지원
- 생산자가 입력 메세지 발행
- 소비자가 메세지를 받아 작업 수행

### 기대효과
- 서비스 또는 서버간 결합이 느슨해져 규모 확장성 보장
- 생산자와 소비자 동시에 활성화 되지 않아도 각각 처리 가능

### 고려사항
- 큐의 크기를 키워 많은 작업이 들어오면 작업 프로세스 추가
- 큐가 비어있는 경우가 많다면 작업 프로세스를 줄임
