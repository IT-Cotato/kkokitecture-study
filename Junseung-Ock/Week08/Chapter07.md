# 분산 시스템을 위한 유일 ID 생성기 설계

### 관계형 데이터 베이스의 기본 키를 사용하면?

분산 환경에서는 적용 불가

### 분산 시스템에서 유일성이 보장되는 아이디 만드는 법

- 다중 마스터 복제
- UUID
- 티켓 서버
- 트위터 스노플레이크 접근법

### 다중 마스터 복제

데이터베이스의 auto_increment 기능 활용

ID 값 구할 때 1만큼 증가시키는 것이 아닌 데이터베이스 서버 개수인 K만큼 증가

#### 단점

- 여러 데이터 센터에 걸쳐 규모를 늘리기 어려움
- ID 유일성은 보장되지만 그 값이 시간 흐름에 맞추어 커지도록 보장하지 못 함
- 서버 추가 삭제 시 잘 동작하기 어려움

### UUID

컴퓨터 시스템에 저장되는 정보를 유일하게 식별하기 위한 128비트 수 → 충돌 가능성 낮음

서버 간 조율 없이 독립적으로 생성 가능

#### 장점

- 만드는 것이 단순. 서버 사이에 조율이 필요 없어 동기화 이슈 X
- 각 서버가 자신이 쓸 ID를 알아서 만드느 구조 → 규모 확장 용이

#### 단점

- ID가 128비트 → 길다
- ID 시간순으로 정렬 불가
- ID에 숫자가 아닌 값이 포함될 수 있음

### 티켓 서버

auto_increment 기능을 갖춘 데이터베이스 서버인 티켓 서버를 중앙 집중형으로 하나만 사용

#### 장점

- 유일성 보장되는 숫자로만 구성된 ID를 쉽게 생성
- 구현이 쉽고, 중소 규모 애플리케이션에 적합

#### 단점

- 티켓 서버가 SPOF 됨
- 장애 발생 시 모든 시스템이 영향을 받음

### 트위어 스노플레이크 접근법

64비트 ID

- 사인 비트 : 1비트 → 양수 음수 구별
- 타임스탬프 : 41비트 → 기원 시각 이후로 경과한 밀리초
    - 시간의 흐름에 따라 큰 값을 가짐 → 시간 순 정렬 가능
- 데이터센터 ID : 5비트 → 32개의 데이터센터 지원
- 서버 ID : 5비트 → 데이터센터당 32개의 서버 사용 가능
- 일련번호 : 12비트 → ID 생성 시 1만큼 증가. 1밀리초가 경과할 때마다 0으로 초기화
    - 같은 밀리초 동안 한 개 이상의 ID를 생성한 경우 0보다 큰 값을 가짐

상황에 맞게 각각의 길이 최적화 가능

EX) 동시성이 낮고 수명이 긴 애플리케이션 → 일련번호 길이 줄이고 타임스탬프 길이 늘림
