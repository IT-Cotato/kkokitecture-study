# 구글 드라이브 설계

## 문제 이해 및 설계 범위 확정

### 기능

- 파일 추가
- 파일 다운로드
- 여러 단말에 파일 동기화
- 파일 갱신 이력 조회
- 파일 공유
- 파일이 편집되거나 삭제되거나 새롭게 공유되었을 때 알림 표시

## 개략적인 설계안 제시 및 동의 구하기

### API

1. 파일 업로드 API
    - 단순 업로드
    - 이어 올리기
2. 파일 다운로드 API
    - PATH → 다운로드할 파일의 경로
3. 파일 갱신 히스토리 API
    - PATH → 갱신 히스토리를 가져올 파일의 경로
    - LIMIT → 히스토리 길이의 최대치

### 한 대 서버의 제약 극복

- 샤딩
- S3
- 메타데이터 데이터베이스
- 파일 저장소

## 동기화 충돌

- 여러 사용자가 같은 문서 편집할 때 발생하는 문제

## 개략적 설계안

- 사용자 단말
- 블록 저장소 서버
- 클라우드 저장소
- 아카이빙 저장소
- 로드밸런서
- API 서버
- 메타데이터 데이터베이스
- 메타데이터 캐시
- 오프라인 사용자 백업 큐

## 상세 설계

- 블록 저장소 서버
    - 델타 동기화
    - 압축
- 높은 일관성 요구사항
    - 캐시에 보관된 사본과 데이터베이스에 있는 원본이 일치
    - 데이터베이스에 보관된 원본에 변경이 발생하면 캐시에 있는 사본을 무효화
- 메타데이터 데이터베이스
    - USER, DEVICE, NAMESAPCE, FILE, FILE_VERSION, BLOCK 등의 정보 저장
- 업로드 절차
    - 파일 메타데이터 추가
        - 추가 요청
        - 업로드 상태 대기로 변경
        - 새 파일 추가되었음을 알림 서비스에 통지
        - 클라이언트에 파일이 업로드되고 있음을 알림
    - 파일을 클라우드 저장소에 업로드
        - 파일을 블록 저장소에 업로드
        - 블록 저장소 서버는 파일을 블록 단위로 쪼개고 압축하고 암호화 한 후 전송
        - 업로드 완료 후 콜백 호출 → API 서버로 전송
        - 메타데이터 DB에 파일의 상태를 완료로 변경
        - 알림 서비스에 파일 업로드가 끝났음을 통지
        - 알림 서비스는 관련된 클라이언트에게 끝났음을 알림
- 다운로드 절차
    - 알림 서비스가 파일이 변경되었음을 알림
    - 확인한 클라이언트가 새로운 메타데이터 요청
    - API 서버는 메타데이터 DB에 새로운 메타데이터 요청
    - API 서버가 이를 반환
    - 클라이언트에게 전달
    - 클라이언트는 블록 다운로드 요청 전송
    - 블록 다운로드
    - 클라우드 저장소는 블록 서버에 요청된 블록 반환
    - 클라이언트에게 블록 반환
- 알림 서비스
    - 롱 폴링
    - 웹소켓
- 저장소 공간 절약
    - 중복 제거
    - 지능적 백업 전략
    - 자주 쓰이지 않는 데이터 아카이빙 저장소로 이동
- 장애 처리
    - 로드밸런서 장애
    - 블록 저장소 서버 장애
    - API 서버 장애
    - 클라우드 저장소 장애
    - 메타데이터 캐시 장애
    - 메타데이터 데이터베이스 장애
    - 알림 서비스 장애
    - 오프라인 사용자 백업 큐 장애
