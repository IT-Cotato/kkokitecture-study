# 안정 해시 설계

## 해시 키 재배치 문제

### 서버 부하를 균등하게 나누는 보편적 방법
-> serverIdx = hash(key) % N(서버의 개수)
- 서버 풀의 크기가 고정되어 있을 때, 데이터가 균등할 때 잘 작동
- 서버가 추가되거나 기존 서버가 삭제되면 문제 발생
  - 대부분의 키가 재배치 -> 캐시 미스 증가
---
## 안정 해시
해시 테이블 크기가 조정될 때 평균적으로 k/n개의 키만 재배치
- k -> 키의 개수
- n -> 슬롯의 개수

### 해시 공간과 해시 링
- SHA-1의 해시 공간은 2^160 - 1
- 이를 구부려 접어 해시 링을 만듬

### 해시 서버
해시 함수를 통해 해시 링 위에 배치

### 해시 키
해시 함수를 통해 해시 링 위에 배치

### 서버 조회
해시 링 위의 키 위치로부터 시계 방향으로 링을 탐색해 가장 먼저 만나는 서버

### 서버 추가
해시 링에 서버 추가 -> 일부 키만 재배치

### 서버 제거
해시 링에 있는 서버 제거 -> 일부 키만 재배치

### 기본 구현 법의 문제
- 서버가 추가되거나 삭제될 때 파티션의 크기를 균등하게 유지하는 것이 불가능
- 키의 균등 분포를 달성하기 어려움
##### 이를 해결하기 위해 가상 노드 기법 사용

### 가상 노드
실제 노드 또는 서버를 가리키는 노드 -> 하나의 서버는 여러 개의 가상 노드를 가질 수 있음
- 가상 노드의 개수 증가
  - 키의 분포가 더 균등해짐
  - 가상 노드 데이터를 저장할 공간 늘어남
  - 타협적 결정(trade off)가 필요함

## 안정 해시의 이점
- 서버 추가 삭제 시 재배치 되는 키의 수 최소화
- 데이터 더 균등하게 분포 -> 수평적 규모 확장성 달성
- 핫스팟 키 문제 줄임 (특정 샤드에 접근이 몰리는 문제 어느정도 방지)

### 실사용 예시
- 아마존 다이나모 db의 파티셔닝 관련 컴포넌트
- 아파치 카산드라 클러스터에서의 데이터 파티셔닝
- 디스코드 채팅 어플리케이션
- 아카마이 cdn
- 매그레프 네트워크 부하 분산기
