# 유튜브 설계

### 기능

- 빠른 비디오 업로드
- 원활한 비디오 재생
- 재생 품질 선택 기능
- 낮은 인프라 비용
- 높은 가용성과 규모 확장성, 안정성
- 지원 클라이언트 : 모바일 앱, 웹브라우저, 스마트 TV

### 규모

- 일간 능동 사용자 : 오백만
- 한 사용자 평균 5개 하루에 시청
- 10%의 사용자가 하루에 1 비디오 업로드
- 비디오 평균 크기 300MB

### 컴포넌트

- 단말 : 컴퓨터, 모바일 폰 등
- CDN : 비디오 저장
- API 서버 : 업로드 URL 생성, 메타데이터 데이터베이스와 캐시 갱신, 사용자 가입 등

## 상세 설계

**비디오 트랜스코딩**

비트레이트 : 비디오를 구성하는 비트가 얼마나 빨리 처리되어야 하는 지를 나타내는 단위

비트레이트 높으면 고화질

**비디오 트랜스코딩이 중요한 이유**

- 원본 비디오는 저장 공간을 많이 차지함
- 단말과 브라우저는 특정 종류의 비디오 포맷만 지원 - 하나의 비디오를 여러 포맷으로 인코딩 해둬야함
- 상황에 맞게 저화질 고화질

**인코딩 포맷**

- 컨테이너 : 비디오 파일, 오디오, 메타데이터를 담는 곳
- 코덱 : 화질을 보존하면서 크기를 줄일 목적으로 고안된 압축 및 해제 알고리즘

### 유향 비순환 그래프 모델

<img width="1270" height="922" alt="Image" src="https://github.com/user-attachments/assets/00320961-1589-4263-a5f4-f1fd49c7053d" />

- 검사 : 좋은 품질의 비디오인지 손상은 없는 지 확인
- 비디오 인코딩 : 다양한 해상도, 코덱, 비트레이트 조합으로 인코딩
- 섬네일 : 사용자 업로드 이미지 or 자동 추출 이미지
- 워터마크 : 비디오에 대한 식별 정보를 이미지 위에 오버레이

### 비디오 트랜스코딩 아키텍처

<img width="1588" height="520" alt="Image" src="https://github.com/user-attachments/assets/d2104444-819c-4f4a-894c-06126d27cf13" />

- 전처리기
    - 비디오 분할
    - DAG 생성
    - 데이터 캐시
- DAG 스케줄러
    - DAG 그래프를 분할하여 각각을 작업 큐에 넣어줌
- 자원 관리자
    - 작업 큐 : 실행할 작업 보관 (우선 순위 큐)
    - 작업 서버 큐 : 작업 서버의 가용 상태 정보 보관
    - 실행 큐 : 현재 실행 중인 작업 및 작업 서버 정보 보관
    - 작업 스케줄러 : 최적의 작업/서버 조합을 골라 해당 서버가 작업을 수행하도록 지시
- 작업 서버
    - DAG에 정의된 작업 수행
- 임시 저장소
    - 보관할 것에 따라 적절한 시스템 선택
- 인코딩된 비디오
    - 최종 결과물

### 최적화

**속도 최적화**

- GOP로 분할하여 병렬적 업로드
- 업로드 센터를 사용자 근거리에 지정
- 모든 절차 병렬화
    - 메시지 큐 도입

**안정성 최적화**

- 미리 사인된 업로드 URL
- 비디오 보호
    - 디지털 저작권 관리
    - AES 암호화
    - 워터마크

**비용 최적화**

- 인기 있는 비디오만 CDN 통해 재생
- 특정 지역 인기 비디오 특정 지역 CDN에 저장

**오류 처리**

- 회복 가능 오류
    - 재시도
- 회복 불가능 오류
    - 오류 코드 반환
