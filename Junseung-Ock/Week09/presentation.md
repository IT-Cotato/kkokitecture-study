# 블룸 필터
> 출처: https://en.wikipedia.org/wiki/Bloom_filter

원소가 집합에 속하는지 여부를 검사하는데 사용되는 확률적 자료 구조

## 구조

- Bloom Filter는 **m 비트 크기의 비트 배열**을 가짐.
- **k 가지 서로 다른 해시 함수**를 사용하며,
  각 해시 함수는 입력된 원소에 대해 0~m-1 범위의 값을 균등한 확률로 출력해야 함.

---

### 지원하는 명령어

- **원소 추가(Add)**
    - 추가하려는 원소에 대해 k개의 해시 값을 계산.
    - 각 해시 값에 대응하는 비트를 1로 설정.
- **원소 검사(Check)**
    - 검사하려는 원소에 대해 k개의 해시 값을 계산.
    - 각 해시 값에 대응하는 비트를 읽음.
    - 모든 비트가 1이면 집합에 속한다고 판단.
    - 하나라도 0이면 집합에 속하지 않는다고 판단.
- ❌ **원소 삭제(Delete)**
    - Bloom Filter는 원소 삭제를 지원하지 않음.

---

### 핵심 포인트

- Bloom Filter는 공간 효율적이고 빠른 집합 판별을 지원.
- 긍정 오류가 발생할 수 있음.
- 부정 오류는 발생하지 않음.

### 긍정 오류

실제로는 집합에 없는 데이터인데, 블룸 필터가 집합에 있다고 잘못 판단하는 경우

**발생 원인 (해시 충돌)**
블룸 필터는 데이터를 추가할 때 여러 개의 해시 함수를 거쳐 나온 인덱스의 비트들을 1로 채움

### Bloom Filter 긍정 오류 예시

1. 데이터 A 추가

- 첫 번째 해시 함수 → 1
- 두 번째 해시 함수 → 4

**배열 상태:**

[0, 1, 0, 0, 1, 0, 0, 0]

---

**2. 데이터 B 추가**

- 첫 번째 해시 함수 → 3
- 두 번째 해시 함수 → 7

**배열 상태:**

[0, 1, 0, 1, 1, 0, 0, 1]

---

**3. 데이터 C 추가**

- 첫 번째 해시 함수 → 4
- 두 번째 해시 함수 → 6

**배열 상태:**

[0, 1, 0, 1, 1, 0, 1, 1]

---

**4. 데이터 X 확인**

- 첫 번째 해시 함수 → 1
- 두 번째 해시 함수 → 7

배열에서 **1번과 7번이 이미 채워져 있음** → 데이터 X가 존재한다고 판단

---

**5. 결과**

- 실제로 데이터 X는 추가하지 않았음
- 그러나 A와 B가 차지한 비트 때문에 X가 있다고 잘못 판단

**긍정 오류 (False Positive) 발생**

Bloom Filter의 특성상 존재하지 않는 데이터가 있다고 잘못 판단할 수 있음

## 부정 오류

실제로는 집합에 있는 데이터인데, 블룸 필터가 집합에 없다고 잘못 판단하는 경우

### Bloom Filter에서 부정 오류가 발생하지 않는 이유

**1. 데이터 추가 시 동작**

- 어떤 데이터가 집합에 추가되면,
  해당 데이터의 모든 해시 함수 결과 위치의 비트가 1로 세팅

---

**2. 데이터 조회 시 검증**

- 특정 데이터를 조회할 때, 해시 함수 결과 위치의 비트를 확인함.
- 만약 그 중 하나라도 0이라면,
  → 그 데이터는 한 번도 추가된 적 없음을 의미

---

**3. 결론**

- 실제로 추가된 데이터는 항상 해시 결과 위치가 1로 설정되어 있음.
- 따라서 조회 시 0이 나올 수 없으므로,부정 오류 발생 불가능

---

### Bloom Filter에서 해시 함수를 여러 개 쓰는 이유

**1. 해시 함수가 하나만 있을 때**

- 각 데이터는 배열에서 딱 한 칸만 차지하게 됨.
- 다른 데이터와 겹칠 확률이 매우 높음 (다른 데이터가 같은 해시 값을 반환하는 경우)

---

**2. 해시 함수가 너무 많을 때**

- 배열이 금방 1로 가득 차버림.
- 어떤 데이터를 조회해도 대부분 있다고 잘못 판단 → 긍정 오류 증가.

---

**3. 해시 함수를 여러 개 쓰는 이유**

- 데이터를 추가할 때 여러 칸에 동시에 표시를 남김.
- 조회할 때 모든 칸이 1이어야만 있다고 판단.
- 하나라도 0이면 즉시 없다 판단 → 정확도 상승.

---

### Counting Filter (카운팅 필터)

**개념**

- 카운팅 필터는 블룸 필터에서 원소 삭제 기능을 지원하도록 변형된 구조.
- 블룸 필터의 버켓 크기가 1비트였던 것을 n비트 카운터로 확장하여 사용.
- 따라서 블룸 필터는 버켓 크기가 1비트인 카운팅 필터라 할 수 있음.

---

**동작 방식**

- **원소 추가(Add):**
  해당되는 버켓의 값을 1 증가시킴.
- **원소 검색(Check):**
  해당 위치의 값이 0이 아닌지 확인하여 존재 여부 판단.
- **원소 삭제(Delete):**
  해당되는 버켓의 값을 1 감소시킴.

---

**오버플로우 문제**

- 버켓 변수는 오버플로우가 발생할 수 있음.
- 이를 방지하기 위해 충분히 큰 자료형을 사용해야 함.
- 오버플로우 발생 시, 블룸 필터의 성질을 유지하기 위해
  → 원소 추가 및 삭제 시 해당 버켓 값을 최댓값으로 설정.

---

**메모리 사용**

- 카운터 크기는 일반적으로 3~4비트.
- 따라서 카운팅 블룸 필터는 기존 블룸 필터보다 3~4배 더 많은 메모리를 사용.

---

**단점**

- 낮은 확장성: 테이블 크기가 고정되어 있음.
- 필터가 수용할 수 있는 최대 키 개수를 미리 알아야 함.
- 범위를 초과해 키가 추가되면 → 긍정 오류 발생 확률 급격히 증가.
