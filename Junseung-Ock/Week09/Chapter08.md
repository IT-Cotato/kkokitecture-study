
# 8장 URL 단축기 설계

### **기본적인 기능**

1. url 단축 : 긴 url을 짧게 줄인다.
2. url 리디렉션 : 축약된 url로 원래 url에 접속
3. 높은 가용성과 규모 확장성, 장애 감내 요구

### **API 엔드포인트**

1. URL 단축용 엔드포인트 : 단축할 URL을 인자로 넣어 이 엔드포인트에 보냄

   인자 : {longUrl : longURLstring}

   반환 : 단축 URL

2. URL 리디렉션용 엔드포인트 : 단축 URL에 대해서 요청이 오면 원래 URL로 보내줌

   GET/api/v1/shortUrl

   반환 : HTTP 리디렉션 목적지가 될 원래 URL (축약 전)


### **URL 리디렉션**

단축 url 받음 → 이를 원래 url로 바꾸어 301 응답 헤더의 location에 넣어 반환

**301 permanently moved**

영구적으로 location 헤더가 지정하는 url에 의해 처리

브라우저는 이 응답을 캐시하여 추후에 같은 단축 url에 대한 요청을 캐시로 처리

장점 : 서버 부하 적음 (처음 한번만 url 서버로 전송되기 때문)

**302 found**

일시적으로 location 헤더가 지정하는 url에 의해 처리

클라이언트의 요청이 언제나 단축 url 서버에 먼저 보내져야 함 (바뀐 경우 대비)

장점 : 트래픽 분석 용이 (클릭 발생률, 발생 위치 추적 유리)

**해시 테이블 사용하여 url 리디렉션 구현**

<단축 url, 원래 url>

원래 url = hashTable.get(단축 url)

### URL 단축

긴 url을 단축시키는 함수 필요

- 입력으로 주어지는 긴 url이 다른 값이면 해시 값도 달라야 함
- 계산된 해시 값은 원래 입력으로 복원될 수 있어야 함

## 상세 설계

### 데이터 모델

해시 테이블에 저장하면 비용적으로 부담이 큼

→ 단축 url, 원본 url 쌍을 관계형 데이터베이스에 저장

### 해시 함수

사용할 수 있는 문자 개수

0-9, a-z, A-Z 총 62개

이와 함께 시스템에서 필요한 url 개수 추정치만큼 생성해야 함

길이가 7이라면 62^7만큼의 url 생성 가능 → 약 3.5조

#### **해시 함수 구현 방식**

- **해시 후 충돌 해소**

알려진 해시 함수를 사용하면 위에서 설정한 길이인 7보다 긴 url이 생성됨

따라서 생성된 url 중 앞에서 7개만 사용 → 충돌 발생 위험

충돌 발생 시 사전에 정한 문자열을 덧붙임

충돌을 확인해야 하므로 오버헤드 발생 → 블룸 필터 사용 시 성능을 높일 수 있음

- **base-62 변환**

수의 표현 방식이 다른 두 시스템이 같은 수를 공유하여 하는 경우에 유용

해시에서 사용할 수 있는 문자가 62개이므로 62진법 사용

유일 id 생성기로 id 생성 후 이를 62진법으로 변환하여 url에 반영

| **해시 후 충돌 해소** | **base-62 변환** |
| --- | --- |
| 단축 url 길이 고정 | 길이 가변적 (id 값 길이에 비례) |
| 유일성 보장 id 생성기 필요 x | 유일성 보장 id 생성기 필요 |
| 충돌 해소 전략 필요 | id가 유일하기 때문에 충돌 발생 x |
| id 기반으로 url을 만들지 않기 때문에 다음에 사용될 url 추측 불가능 | id가 1씩 증가하는 경우 다음 url을 알아낼 수 있어 보안상 문제 발생 가능 |

### URL 단축기 상세 설계

1. 입력으로 긴 url 받음
2. db에 해당 url 있는지 검사
3. 있다면 해당 url의 단축 url을 가져와 반환
4. 없다면 새로 들어온 url 이므로 유일한 id 생성 → db의 기본 키
5. 62진법으로 id 를 단축 url로 만듦
6. id, 단축 url, 원래 url로 새 db 레코드를 만든 후 단축 url을 클라이언트에게 반환

### URL 리디렉션 상세 설계

1. 사용자가 단축 url 클릭
2. 로드밸런서가 해당 클릭으로 발생한 요청을 웹 서버에 전달
3. 단축 url이 캐시에 있는 경우 원래 url을 바로 꺼내 반환
4. 캐시에 없다면 db에서 꺼냄 → db에 없는 경우 잘못 입력한 경우임
5. db에서 꺼낸 url을 캐시에 넣은 후 클라이언트에게 반환
