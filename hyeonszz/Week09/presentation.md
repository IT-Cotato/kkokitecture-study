## Bloom filter

사용 배경

- 단축 URL을 생성할 때 **해시 후 충돌 해소** 기법을 사용하면 한 번 이상 데이터베이스 질의를 해야하므로 오버헤드가 크다. 데이터베이스 대신 블룸 필터를 사용하면 성능을 높일 수 있다.

블룸 필터는 원소가 집합에 속하는지 여부를 검사하는데 사용되는 확률적 자료 구조이다. 

- **긍정오류**: 어떤 원소가 집합에 속한다고 판단되었지만 실제로는 원소가 집합에 속하지 않는 오류
- **부정오류**: 원소가 집합에 속하지 않는다고 판단되었는데 실제로는 원소가 집합에 속하는 오류

블룸 필터 특징

- 블룸 필터에 의해서 긍정오류가 발생하는 것은 가능하지만, 부정오류는 절대로 발생하지 않는다
- 집합에 원소를 추가하는 것은 가능하나, 집합에서 원소를 삭제하는 것은 불가능 하다
- 집합 내 원소의 숫자가 증가할수록 긍정 오류 발생 확률이 증가한다

### 구조

---

- m비트 크기의 비트 배열 구조
- k가지의 서로 다른 해시 함수 사용
    - 각 해시 함수는 입력된 원소에 대해 m가지의 값을 균등한 확률로 출력해야 한다.
- 집합에 원소를 추가하는 명령어와 원소가 속하는지 검사하는 명령어를 지원한다
    - 삭제하는 명령어는 존재하지 않는다
        - 원소를 추가하는 경우, 추가하려는 원소에 대해 k가지의 해시 값을 계산한 다음 각 해시 값에 대응하는 비트를 1로 설정한다
        - 원소를 검사하는 경우, 검사하려는 원소에 대해 k가지의 해시 값을 계산한 다음 각 해시 값에 대응하는 비트를 읽는다. 모든 비트가 1인 경우 속한다고 판단하며 나머지는 속하지 않는다고 판단한다.

ex) m=18, k=3 & x,y,z 존재

⇒ w의 세 해시값 중 블룸 필터 값이 0인 경우가 존재하기 때문에, 해당 값은 집합에 **속하지 않는다**고 판단할 수 있다

### 성질

---

원소 추가와 원소 검사에 걸리는 시간은 O(K)로, 집합에 포함되어 있는 원소 수와 무관하다. 

- 원소를 n개 추가했을 때, 특정 비트가 0일 확률

### 확장

---

#### Counting filter

카운팅 필터는 블룸 필터에서 필터를 재생성하지 않고도 원소의 삭제가 가능하도록 변형된 것이다. 

- 블룸 필터 → 배열 내 각 버켓의 크기가 1비트
- 카운팅 필터 → n비트로 확장하여 카운터로 사용

⇒ 블룸 필터는 배열 버켓 크기가 1비트인 카운팅 필터라고 할 수 있다

| 구분 | 블룸 필터 | 카운팅 필터 |
| --- | --- | --- |
| 버킷 값 | 0 or 1 | 0,1,2,3,… |
| 의미 | 지나갔는지 여부 | 몇 번 지나갔는지 |
| 삭제 여부 | 불가능 | 가능 |

**[동작 방식]**

- 삽입
    - 해시로 나온 버킷들의 값을 +1 증가
- 조회
    - 해당 버킷들이 모두 0이 아니면 존재한다고 판단
- 삭제
    - 해당 버킷들의 값을 1 감소

**[오버플로우 문제]**

- 버킷은 정해진 비트 수라서 최댓값이 존재함 → 계속 증가하면 오버플로우 발생 가능

해결방법

- 오버 플로우 발생 시 최대값으로 고정
- 블룸 필터의 부정 오류 방지 성질을 유지하기 위해

**[메모리 사용량]**

- 카운팅 필터는 각 버킷이 1비트가 아니라 여러 비트를 사용하기 때문에 메모리가 증가한다
- 같은 정확도를 유지한다면 정적 블룸 필터가 더 적은 메모리로도 가능하다

**[확장성]**

- 테이블 크기가 고정되어 있으므로 미리 최대 데이터 수를 예측해야 한다
- 용량 초과 시 충돌이 증가하여 부정 오류 확률 급격히 상승한다

카운팅 필터는 **삭제가 가능**하지만

**메모리**를 더 쓰고, **오버플로우** 관리가 필요하며 **확장성**에 약하다
