# ch5. 안정 해시 설계

#### 안정 해시

: 해시를 사용해 요청을 분산하는 방법으로, 요청 또는 데이터를 서버에 균등하게 나누기 위해 보편적으로 사용하는 기술

#### 해시 키 재배치(rehash) 문제

N개의 캐시 서버에 부하를 균등하게 나누는 법

```bash
serverIndex = hash(key) % N (N은 서버의 개수)
```

: 전통적인 해시 테이블 → 모듈로(%) 연산을 이용

- 이 방법은 서버 풀(server pool)의 크기가 고정되어 있을 때, 데이터 분포가 균등할 때는 잘 동작하지만 **서버가 추가**되거나 **기존 서버가 삭제**되면 문제가 생긴다.
- 대부분의 해시 대상이 재분배되며 확장성에 취약하다

#### 안정 해시 (consistent hash)
해시 테이블 크기가 조정될 때 평균적으로 오직 k/n개의 키만 재배치하는 해시 기술 (k: 키의 개수/n: 슬롯의 개수)

- 모듈로 연산(%)으로 대상을 탐색하지 않으며, 해시 링(Hash Ring)을 만들어 링 위에서 첫번째 만나는 것을 대상으로 한다

**해시 공간과 해시 링**

해시 공간의 시작과 끝을 붙여 원형 리스트로 사용하면 해시 링(hash ring)이 만들어진다.

**해시 서버**

서버 IP나 이름을 해시 링 위의 어느 지점에나 배치할 수 있다.

**해시 키**

캐시할 키 또한 링 위의 어느 지점에 배치할 수 있다.

- 기존의 해시가 아닌 균등 분포 (uniform distribution) 해시 함수를 사용해서 원형에 골고루 분포시킨다

**서버 조회**

어떤 키가 저장되는 서버는, 해당 키의 위치로부터 시계 방향으로 링을 탐색해 나가면서 만나는 첫 번째 서버이다. 

- 해당 hash key로부터 시계방향으로 서버를 탐색하여 만난 첫번째 서버를 조회한다

**서버 추가**

위의 상황이라면, 서버를 추가하더라도 키 가운데 일부만 재배치하면 된다.

**서버 제거**

하나의 서버가 제거되면 키 가운데 일부만 재배치된다

기본 구현법의 두 가지 문제

- 안정 해시 알고리즘
    - 서버와 키를 균등 분포 해시 함수를 사용해 해시 링에 배치한다
    - 키의 위치에서 링을 시계 방향으로 탐색하다 만나는 최초의 서버가 키가 저장될 서버이다

**문제1**. 서버가 추가되거나 삭제되는상황을 감안하면 파티션의 크기를 균등하게 유지하는게 불가능하다

- 파티션: 인접한 서버 사이의 해시 공간
- 어떤 서버는 굉장히 큰 해시 공간을 할당 받고, 어떤 서버는 굉장히 작은 해시 공간을 할당 받는 상황이 가능하다

**문제2**. 키의 균등 분포를 달성하기 어렵다

- key 배치 자체가 한쪽 파티션에 몰릴 수 있다

**해결책**: 가상 노드(virtual node) 또는 복제(replica) 사용

**가상 노드 (virtual node)**

: 실제 노드 또는 서버를 가리키는 노드로서, 하나의 서버는 링 위에 여러 개의 가상 노드를 가질 수 있다

- 가상 노드의 개수를 늘리면 키의 분포는 점점 더 균등해진다
- 노드의 개수가 늘어나면 표준편차가 작아져서 데이터가 고르게 분포되지만 그만큼 가상노드 데이터를 저장할 공간이 더 많이 필요해진다
- 타협적 결정(tradeoff)이 필요하다

ex) 서버 1을 링에 배치할 때 s1_0, s1_1, s1_2 등 여러 가상 노드를 배치하여 사용한다

**안정 해시의 이점**

- 서버가 추가되거나 삭제될 때 재배치되는 키의 수가 최소화된다
- 균등한 데이터 분포로 수평적 규모 확장성을 달성하기 쉽다
- 핫스팟(hotspot) 키 문제를 줄인다
    - 핫스팟: 특정 key에 요청이 몰려서 한 서버만 과부하되는 현상
