## 1. 엣지 컴퓨팅

: 데이터가 생성되는 가까운 곳에서 처리하는 방식

→ 서버와 클라이언트 사이의 거리를 줄여 기능을 최적화하기 위한 기술

- **기존**(클라우드에서 처리) → **엣지 컴퓨팅**(사용자/장치 근처에서 처리)


#### 기존 방식 (클라우드 방식)

1. 스마트폰/카메라가 데이터 생성
2. 인터넷 통해 멀리 있는 서버(클라우드)로 보냄
3. 서버에서 처리
4. 결과 다시 돌려줌

[문제]

* 느림 (왕복 시간)
* 데이터 많으면 비용/부담 큼

#### 엣지 컴퓨팅 방식

1. 데이터 생성
2. 근처 디바이스에서 바로 처리 (카메라, IoT, 스마트폰 등)
3. 결과 즉시 사용

[장점]

* latency 감소
* 대역폭 절약

  * 대역폭: 한 번에 보낼 수 있는 데이터 양 (네트워크 용량)

    * 영상 스트리밍 = 데이터 많이 필요 (대역폭 많이 씀)
    * 텍스트 = 데이터 적음 (대역폭 적게 씀)
  * 대역폭이 부족하면 → 속도 느려지고 끊김 발생, 서버 부담 증가, 비용 증가
* 서버 부하 감소
* 실시간 처리 가능

EX) 머신러닝 모델

1. 클라우드에서 AI 학습시킴
2. 학습 끝난 AI를 기기에 넣음
3. 기기에서 바로 판단

⇒ 클라우드에서 모델을 학습시키고, 학습된 모델을 디바이스에 배포해 엣지에서 실시간으로 추론

## 2. 네트워크 엣지

: 사용자와 가장 가까운 네트워크 지점

ex) 사용자 기기, IoT 장치, 라우터, ISP, 지역 엣지 서버

→ 클라우드보다 물리적으로 가까운 위치

---

## 3. 컴퓨팅 방식 발전 흐름

| 단계       | 특징             |
| -------- | -------------- |
| 초기 컴퓨팅   | 중앙 컴퓨터에서만 실행   |
| 개인 컴퓨팅   | 각 PC에서 실행      |
| 클라우드 컴퓨팅 | 데이터센터에서 실행     |
| 엣지 컴퓨팅   | 사용자 가까운 곳에서 실행 |

## 4. 왜 엣지 컴퓨팅이 필요한가?

### <기존 클라우드 방식의 한계>

* 서버가 멀리 있음
* 네트워크 지연 발생
* 데이터 전송량 많음
* 서버 부하 증가

→ 처리를 아예 가까운 곳에서 해버리자!

### <기존 클라우드 방식의 문제 상황>

* 카메라 → 영상 전부 서버로 전송
* 서버 → 움직임 감지 처리

문제점: 트래픽이 많고 서버 부하가 큼

### <엣지 컴퓨팅 방식>

* 카메라 자체에서 움직임 감지
* 필요한 영상만 서버 전송

→ 데이터 전송량 ↓, 서버 부하 ↓, 속도 ↑

### <엣지 컴퓨팅의 효과>

* 데이터 전송량 감소

  * 전체 데이터를 보내지 않고 필요한 정보만 전송
* 서버 부하 감소

  * 일부 연산을 디바이스가 수행 → 서버 부담 분산
* 응답 속도 향상

  * 데이터를 멀리 보내지 않고 즉시 처리 가능

---

## 5. 주요 사용 사례

(1) IoT 장치

* 센서, 스마트홈 기기
* 실시간 처리 필요

(2) 자율주행 자동차

* 서버 기다리면 사고남
* 즉시 판단 필요

(3) 보안 시스템

* CCTV 실시간 분석

(4) 화상회의

* 지연 최소화

(5) CDN + 엣지

* 콘텐츠 전달 + 로직 처리

(6) 의료 장치

* 즉각 반응 필요

---

## 6. 단점

* 보안 위험 증가

  * 장치가 많아지면 공격 지점 증가
* 하드웨어 비용

  * 각 장치에 연산 능력 필요
* 관리 복잡성

  * 분산된 환경 관리 어려움

---

## 7. 결론

엣지 컴퓨팅 = 클라우드 대신 사용자 가까운 곳에서 처리하는 방식

* 지연 ↓
* 트래픽 ↓
* 서버 부하 ↓
* 실시간 처리 ↑

## CDN vs Edge Computing

* CDN은 엣지 컴퓨팅의 특화된 형태

  * 엣지 컴퓨팅 중에서도 **콘텐츠 전달에 특화된 초기 형태**

#### [차이점]

### CDN (Content Delivery Network)

* **목적**: 웹페이지, 이미지, 비디오 등 정적 콘텐츠를 빠른 속도로 전달
* **방식**: 중앙 서버 데이터를 전 세계 캐시 서버에 저장 후 배포
* **특징**: 데이터 저장 및 전달 중심

### 엣지 컴퓨팅 (Edge Computing)

* **목적**: 디바이스 근처에서 데이터 실시간 처리/분석
* **방식**: IoT 기기나 사용자 근처 서버에서 로직 실행
* **특징**: 데이터 연산(컴퓨팅) 중심

----

### 비교표

| 특징   | CDN          | 엣지 컴퓨팅       |
| ---- | ------------ | ------------ |
| 주 목적 | 정적 콘텐츠 배포    | 실시간 데이터 처리   |
| 위치   | 사용자 근처 캐시 서버 | 디바이스 근처      |
| 데이터  | 정적 콘텐츠       | 동적 데이터       |
| 역할   | 전달           | 연산 + 처리      |
| 사례   | 넷플릭스, 웹사이트   | 자율주행, 스마트팩토리 |

⇒ CDN = 가까운 곳에서 가져오기

⇒ 엣지 컴퓨팅 = 가까운 곳에서 처리하기

## 엣지 컴퓨팅 작동 방식

| 구분    | 방향        | 의미            |
| ----- | --------- | ------------- |
| 업스트림  | 디바이스 → 서버 | 데이터를 서버로 올림   |
| 다운스트림 | 서버 → 사용자  | 데이터를 사용자에게 전달 |


### ① 업스트림 (Upstream)

: 디바이스가 데이터를 서버로 보내기 전에 엣지에서 처리

* CCTV → 움직임 있을 때만 전송
* 센서 → 이상값만 전송
* 스마트카 → 중요한 건 로컬 처리

→ 핵심: **데이터 전송량 감소**


### ② 다운스트림 (Downstream)

: 서버 → 사용자 전달 시 엣지에서 처리

* 가까운 엣지 서버에서 처리 후 전달
* 게임, 스트리밍, 화상회의

→ 핵심: **응답 속도 향상**


| 구분 | 업스트림      | 다운스트림    |
| -- | --------- | -------- |
| 방향 | 디바이스 → 서버 | 서버 → 사용자 |
| 목적 | 데이터 줄이기   | 빠른 전달    |
| 기술 | 엣지 컴퓨팅    | CDN      |
| 기능 | 필터링, 분석   | 캐싱       |

## CDN과의 관계

CDN은 엣지 컴퓨팅의 특화된 형태이며
**주로 다운스트림에서 사용**되지만 업스트림에도 관여함

### ① CDN의 역할 (다운스트림)

* 이미지, 영상 등을 사용자 가까운 서버에 저장
* 요청 시 빠르게 전달

ex) 넷플릭스, 웹사이트 이미지

### ② CDN의 업스트림 역할 (현대 CDN)

* Cloudflare Workers, AWS Lambda@Edge 등
* 서버 도달 전에 엣지에서 처리

ex) 인증, A/B 테스트, 봇 차단

→ 이 경우 CDN이 업스트림 역할까지 수행
