# 지연 시간과 처리량의 이해

> 출처 : https://community.cadence.com/cadence_blogs_8/b/fv/posts/understanding-latency-vs-throughput
>
# 개요

- **HLS(High-Level Synthesis)** 방법론이 채택되면서 '시스템 설계자'와 '하드웨어 설계자의 장벽이 상당히 줄어들었다.
    - HLS(High-Level Synthesis)
        - C, C++, SystemC와 같은 상위 수준의 프로그래밍 언어로 기술된 알고리즘을 하드웨어 설계 언어인 HDL(Verilog, VHDL 등)의 RTL(Register-Transfer Level) 코드로 자동 변환해 주는 기술/프로세스
        - 소프트웨어 개발자가 작성한 논리적 동작 → 하드웨어가 이해할 수 있는 물리적 회로 구조로 설계해주는 하드웨어판 컴파일러
- '시스템 설계자'와 '하드웨어 설계자 모두 모델을 정의할 때 동일한 입력 언어(C++, SystemC), 용어를 접하게 되었다.
- ‘하드웨어 설계자’는 과거에는 거의 접할 기회가 없었던 시스템 관점의 용어들을 접하게 되었다.

이 글의 목적은 혼동되고 같은 의미로 사용되는 두 가지 시스템 용어인 **지연 시간(latency**)와 **처리량(throughput)**의 개념을 명확히 구분하고 정의하기 위함이다.

# 용어 정의

## 지연 시간 **(latency**)

- 어떤 동작을 수행하거나 결과를 도출하는 데 필요한 **시간**
- 시간 단위(시, 분, 초, 나노초 또는 클록 주기)로 측정

## 처리량 **(throughput)**

- 단위 시간당 실행되는 **작업 수** 또는 생성되는 결과 수
- 단위 시간당 생성되는 결과물(cars/day, bits/sec, samples/sec 등)
- 메모리 시스템의 처리량을 나타낼 때 **메모리 대역폭**이라는 용어를 사용하기도 한다.

# 예시

자동차 한 대를 생산하는 데 8시간이 걸리고, 공장에서는 하루에 총 120대의 차를 생산한다.

- 지연 시간 : 8시간
- 처리량 : 120대/일 또는 시간당 5대

# 하드웨어 설계 예시

설계자가 다음과 같은 특징을 가진 통신 장치용 하드웨어를 설계하는 임무를 맡았다.

| 항목 | 사양 값 |
| :--- | :--- |
| 클록 주파수 (Clock Frequency) | 100 MHz (1주기 = 10ns) |
| 가용 계산 시간 (Time available) | 1000 ns |
| 목표 처리량 (Throughput) | 640 Mbits / second |
| 출력 데이터 폭 (Word width) | 64 bits |

## 하드웨어 설계자 관점에서의 변환

- 지연 시간 = 1000ns ÷ 10ns = 100 클록 주기
    - 하드웨어적으로 100 클록 주기 안에 계산이 끝나야 함
- 처리량 = (640M bits/s) ÷ (64 bits/word) = 10M words/s
    - 클록 주기로 환산하면, (100M clock/s) ÷ (10M words/s) = 10 clock periods / word
    - 즉, 10 클록마다 1개의 워드를 내보내야 함
        - Word : 하드웨어나 CPU가 한 번에 처리하는 데이터의 기본 단위

클록 주기 단위로 표현되는 지연 시간과 워드 간 사용 가능한 클록 주기 수로 표현되는 처리량은 설계자가 성능 사양에 따라 원하는 하드웨어를 제작하는 데 사용할 수 있는 매개변수이다.

### 변환을 하는 이유

- 물리적 한계 확인
    - 하드웨어는 클록 한 번(10ns)에 전자가 이동할 수 있는 거리가 물리적으로 정해져 있다.
    - 변환을 통해  해당 연산이 단일 클록 내에 수행 가능한 임계 경로(Critical Path)를 초과하는지 파악하고, 이를 최적의 단계로 분할(Pipelining) 설계해야 함을 판단할 수 있다.
- 자원 결정
    - "10 클록마다 결과가 나와야 한다"는 걸 알아야 ALU를 하나만 쓸지, 여러 개를 병렬로 배치할지 결정할 수 있다.

### 하드웨어 설계 프로세스

| 단계 | 수행 작업 |
| :--- | :--- |
| 1. 스펙 분석 | 640Mbps, 100MHz 등 목표 수치 확인 |
| 2. 단위 변환 | 100 클록(지연), 10 클록(간격) 등 설계 매개변수 계산 |
| 3. 아키텍처 설계 | 파이프라인 단계를 몇 개로 할지, 병렬 처리 여부 결정 |
| 4. HLS/RTL 구현 | C++이나 Verilog로 실제 로직 코딩 |


# 주의할 점

- 일부 설계 툴에서는 처리량을 시간 단위당 처리량이 아닌, 클록 주기로 표시한다.
- 처리량은 비율(Rate)이므로 주기로 표기하는 것은 틀린 방식이지만 편의상 ‘10’처럼 주기로 표현하는 경우가 있으니 주의해야 한다.
    - 10 : 10 클록 주기당 하나씩
